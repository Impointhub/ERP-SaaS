# ADR-001

### 1. ADR-001 — Penamaan Group pada Tree COA

#### Problem

Pada struktur COA berbentuk tree, perlu ditentukan apakah nama group/folder boleh digunakan lebih dari satu kali atau harus unik. Jika nama group boleh kembar, ada risiko kebingungan saat pencarian, audit log, dan navigasi. Jika harus unik secara global, struktur menjadi kurang fleksibel dan tidak mengikuti pola tree pada umumnya.

```
ASET
├── Aset Lancar
│    └── Kas
└── Aset Tetap
     └── Kas
```

#### Opsi

**Opsi 1 — Nama Group Boleh Kembar di Semua Lokasi**

* ✅ Kelebihan: fleksibel mengikuti kebutuhan bisnis; mirip Windows Explorer, Google Drive, SharePoint; tidak memaksa user membuat nama berbeda; mempermudah migrasi/import struktur dari sistem lain
* ❌ Kekurangan: risiko human error lebih tinggi; dropdown selection berpotensi membingungkan; audit log perlu menampilkan path lengkap; search menjadi ambigu

**Opsi 2 — Nama Group Harus Unique Global**

* ✅ Kelebihan: search lebih mudah; audit log lebih sederhana; reporting lebih mudah dibaca; mengurangi kemungkinan salah pilih group
* ❌ Kekurangan: tidak fleksibel untuk berbagai struktur perusahaan; user harus membuat nama tambahan yang sebenarnya tidak diperlukan; menyulitkan migrasi dari sistem lain; tidak mengikuti pola tree structure umum

**Opsi 3 — Nama Group Unique Dalam Parent yang Sama**

* ✅ Kelebihan: mengikuti pola tree structure modern; tetap fleksibel untuk berbagai kebutuhan bisnis; menghindari duplikasi pada level yang sama; struktur lebih mudah dipahami user; mempermudah import dan migrasi data (search perlu menampilkan breadcrumb/path)
* ❌ Kekurangan: audit log perlu menyimpan path folder

#### Decision

**Option 3 — Nama group harus unik dalam parent yang sama.** Validasi: `(parent_id + group_name)` harus unique.

```
✅ Valid
ASET
├── Kas
└── Piutang

✅ Valid
ASET
├── Aset Lancar → Kas
└── Aset Tetap  → Kas

❌ Tidak Valid
ASET
├── Kas
└── Kas
```

#### Reasoning

Tree folder pada dasarnya adalah struktur navigasi, bukan identitas utama data accounting — identitas utama COA adalah Account Code dan Account ID, bukan nama group. Pendekatan unique per parent memberi keseimbangan terbaik antara usability dan fleksibilitas, sekaligus mencegah duplikasi yang membingungkan pada level yang sama. Pola ini juga konsisten dengan Windows Explorer, Linux File System, SharePoint, dan aplikasi enterprise pada umumnya.
